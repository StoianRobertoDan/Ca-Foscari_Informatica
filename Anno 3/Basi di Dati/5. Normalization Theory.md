The *normalization theory* is a systematic approach to organizing data within a relational database to reduce redundancy and improve data integrity.
- **Problematic properties to avoid**:
	- Redundancy of information.
	- Loss of information.
	- Inability to represent certain information.
- **Functional dependencies**:
	- Given the relation schema $R(T)$ (with T attributes and $X, Y\subseteq T$), a *functional* *dependency* is a constrain of the form $X\rightarrow Y$ ($X$ **functionally determines** $Y$). 
	- For any legal instances of $R$: $$ \forall t_{1},t_{2}\in r \ | \ t_{1}(X) = t_{2}(X) \Rightarrow t_{1}(Y) = t_{2}(Y) $$
	- Given a set F of functional dependencies, $F\models X\rightarrow Y$ ($F$ **logically implies** $X\rightarrow Y$) if every instance of $R$ that satisfies $F$ also satisfies $X\rightarrow Y$.
- **Armstrong's axioms**:
	- The *3 Armstrong's axioms* are sound and complete:
		- *Reflexivity*: $$\mbox{if } Y\subseteq X \Rightarrow X \rightarrow Y$$
		- *Augmentation*: $$ \mbox{if } X \rightarrow Y \cap Z \subseteq T \Rightarrow XZ \rightarrow YZ $$
		- *Transitivity*: $$ \mbox{if } X \rightarrow Y \cap Y \rightarrow Z \Rightarrow X \rightarrow Z $$
	- **Inferred rules** ($F\vdash X\rightarrow Y \mbox{ iff } X\rightarrow Y$ can be inferred from $F$ using Armstrong's axioms): 
		- *Union*: $\mbox{if } X \rightarrow Y \cap X \rightarrow Z \Rightarrow X \rightarrow YZ$
		- *Decomposition*: $\mbox{if } X \rightarrow YZ \Rightarrow X \rightarrow YZ$
		- *Weakening*: $\mbox{if } X \rightarrow Y \Rightarrow XZ \rightarrow Y$
- **Closure of a set of functional dependencies**:
	- Given a set $F$ of functional dependencies, the *closure* of $F$ denoted by $F^{+}$ is: $$ F^{+} = \{X \rightarrow Y \ |\  F\vdash X \rightarrow Y\}$$
	- To compute the closure $F^{+}$ has a complexity of $2^{n}$ (exponential) so it is inefficient.
- **Closure of a set of attributes**:
	- Given a schema $R(T,F)$ and $X\subseteq T$, the *closure* of $X$ denoted by $X^{+}$ or $X^{+}_{F}$ is: $$ X^{+} = \{A \in T \ |\  F\vdash X \rightarrow A\} $$
	- $F\models X\rightarrow Y$ iff $Y\subseteq X^{+}_{F}$
	- Algorithm to compute $X^{+}$:
		- $X^{+} = X$
		- While (Changes to $X^{+}$)
			- For each $Y\rightarrow Z \in F$
				- If $Y\subseteq X^{+}$ and  $Z \nsubseteq X^{+}$ 
					- $X^{+} = X^{+}+Z$
	- To compute the closure $X^{+}$ has a complexity of $O(n\_attributes * n\_dependencies * min(n\_attributes, n\_dependencies))$ 
- **Key**:
	- Given the scheme $R(T,F)$, an attribute $X\subseteq T$ is a *key* iff:
		- $X\rightarrow T\in F^{+}$ 
		- $\forall Y\subset X\Rightarrow Y\rightarrow T\notin F^{+}$
	- An attribute is called prime iff is part of a key.
	- Properties of a *candidate key*:
		- If an attribute does no appear on the right-hand side of any functional dependency, it must be part of any candidate key.
		- If an attribute does appear on the right-hand side of some functional dependencies but does not appear in any left-hand side, it can't be in any candidate key.
	- To check a *candidate key*:
		- Compute it's closure.
		- Check if it's equal to the initial set of attributes.
		- Check if it can be minimized.
	- Algorithm to find a key:
		- $K = T$
		- For each $A\in T$
			- If $(K - {A})^{+}_{F} = T$
				- $K = K-A$
	- Algorithm to find all keys:
		- Candidate keys are denoted by $X::(Y)$ where $X$ is the set of attributes to test for closure and Y the set of possible attributes to add to the key.
		- Algorithm:
			- $Z = \{A\in T\ |\ \forall X\rightarrow Y\in F: A\notin Y\}$  (attributes not on the right side).
			- $V = \{A\in T\ |\ \forall X\rightarrow Y\in F: A\notin X\}$  (attributes not on the left side).
			- Cand = $[Z::(T-(Z\cup V))]$
			- Keys = \[]
			- While (Cand not empty)
				- $X::(Y) =$ head(Cand)
				- Cand = tail (Cand)
				- If $\nexists K\in Keys : K\subset X$
					- If $X^{+}_{F} = T$
						- Keys = Keys + X
					- Else 
						- B\[] = $Y-X^{+}_{F}$
						- For each $I \in B[1,...,n]$
							- Cand = Cand + $XB[0]::(I)$
- **Cover of sets of dependencies**:
	- *Equivalent*:
		- Two sets of functional dependencies $F$ and  $G$ are *equivalent*, denoted by $F\equiv G$, iff $F^{+} = G^{+}$.
		- To test it, every dependency in $F$ must be in $G^{+}$ and viceversa.
	- *Cover*:
		- If $F\equiv G$ than $F$ is a cover of $G$.
	- *Properties*:
		- Given  $X\rightarrow Y \in F$, X has a **extraneous attribute** $A$ if $(X-A)\rightarrow Y \in F^{+}$
		- Given $X\rightarrow Y$, is a **redundant dependency** iff $X\rightarrow Y\in (F-\{X\rightarrow Y\})^{+}$
		- F is called a **canonical cover** iff:
			- Every right side in $F$ is a single attribute.
			- No attribute on any left side is *extraneous attribute*.
			- No dependency in F is redundant.
	- Algorithm for a canonical cover:
		- $G = \{X\rightarrow A \ |\ \exists Y: X\rightarrow Y\in F\wedge A\in Y\}$ (only single attributes on right side)
		- For each $X \rightarrow A\in G \ |\  |X|>1$ (FD with multiple attributes on the left side).
			- $Z=X$
			- For each $B\in X$
				- If $A\in (Z-B)^{+}$
					- $Z=Z-B$ (remove extraneous attributes on the left side).
			- $G = (G-\{X\rightarrow A\})\cup \{Z\rightarrow A\}$
			- For each $X\rightarrow A\in G$
				- If $A\in X^{+}_{G-\{X\rightarrow A\}}$
					- $G=G-{X\rightarrow A}$ (remove redundant dependencies).
- **Decomposition**:
	- A *decomposition* of a schema $R(T)$ is the substitution of $R(T)$ with a set of schemas $R_{i}(T_{i})$ such that $\cup T_{i} = T$.
	- Projection:
		- Given the schema $R(T,F)$ and $T_{i}\subseteq T$, the projection of $F$ onto $T_{i}$ is: $$\pi_{T_{1}} (F) = \{X\rightarrow Y\in F^{+}\ |\ X,Y\subseteq T_{i}\}$$
		- Algorithm:
			- For each $X\subset T_{i}$
				- $Y=X^{+}-X$
				- Return $X\rightarrow Y\cap T_{i}$
	- *Data preserving decomposition*:
		- Given a schema $R(T,F)$, the decomposition $\rho = \{R_{1},...,R_{n}\}$ is data preserving if for every legal instance $r$ of $R$: $$ r = (\pi_{T_{1}}(r))\vartriangleright\vartriangleleft ... \vartriangleright\vartriangleleft (\pi_{T_{n}}(r))$$
		- That is, every legal instance of $r$ is the natural join of its projections.
		- Given the decomposition $\rho = \{R_{1}(T_{1}), R_{2}(T_{2})\}$, it is data preserving iff $T_{1}\cap T_{2}\rightarrow T_{1} \mbox{ or } T_{2}\in F^{+}$.
	- Dependency preserving decomposition:
		- Given a schema $R(T,F)$, the decomposition $\rho = \{R_{1},...,R_{n}\}$ is dependency preserving iff $\cup \pi_{T_{i}}(F) \equiv F$.
		- Algorithm to compute $X^{+}_{G}$ with $G=\cup \pi_{T_{i}}(F)$:
			- $X^{+}_{G} = X$
			- While $X^{+}_{G}$ changes
				- For each $R_{i}(T_{i})\in\rho$
					- $X^{+}_{G}=X^{+}_{G}\cup ((X^{+}_{G}\cap T_{i})^{+}_{F}\cap T_{i})$
		- Algorithm to check decomposition:
			- For each $X\rightarrow Y\in F$
				- If $Y\nsubseteq X^{+}_{G}$
					- Return false
			- Return true
	- Given a dependency preserving decomposition $\rho = \{R_{i}(T_{i},F_{i})\}$ such that a $T_{j}$ is a superkey for $R(T,F)$, then $\rho$ is data preserving.
- **Normal forms**:
	- **BCNF**:
		- Given a schema $R(T,F)$ is in *BCNF* iff for each $X\rightarrow Y\in F$, $X$ is a superkey.
			- If $F$ is in canonical cover, is in *BCNF* if for each $X\rightarrow Y\in F$, $X$ is a key.
		- The algorithm to check if a single relation schema is BCNF has complexity $O(ap^{2})$ while the algorithm to convert into BCNF is exponential.
		- The algorithm:
			- $\rho = \{R_{1}(T_{1},F_{1})\}$
			- $n=1$
			- While $\exists R_{i}(T_{i},F_{i})\in\rho$ not in BCNF because of $X\rightarrow Y$
				- $n++$
				- $T' = X^{+}_{F}$
				- $T''=T_{i}-(T'-X)$ or $X\cup (T_{i}-T')$
				- $F'= \pi_{T'}(F_{i})$
				- $F''= \pi_{T''}(F_{i})$
				- $\rho =\rho - R_{i}(T_{i},F_{i}) + \{R_{i}(T',F'),R_{n}(T'',F'')\}$
		- BCNF is not always dependency preserving but is always data preserving and removes anomalies.
	- **3NF**:
		- Given a schema $R(T,F)$ is in *3NF* iff for each $X\rightarrow Y\in F$, either:
			- $X$ is a superkey.
			- $Y\notin X$ and is prime.
		- BCNF decomposition is by definition 3NF but not always viceversa.
		- The algorithm to convert into 3NF has complexity $O(a^{2}p^{2})$.
		- Algorithm:
			- Compute a canonical cover $G$ of the functional dependencies and have $\rho = \{\}$.
			- Compress in $G$  any functional dependency with the same left-hand side into one. ($X\rightarrow A_{1},...,X\rightarrow A_{n} = X\rightarrow A_{1},...,A_{n}$).
			- For each $X\rightarrow Y \in G$ add a schema in  $\rho = \rho+XY$.
			- Delete from $\rho$ every schema already contained in another schema.
			- If the final set of relation schemas does not include a schema whose attributes are a superkey, add a schema with attributes $W$ where $W$ is a key.
		- 3NF is always data and dependency preserving but can have anomalies
